# RepoOnboard V0.1 技术架构方案

任务：T-0001 — Complete Technical Architecture Proposal

日期：2026-09-08

状态：PROPOSED — 已按 T-0002 技术评审修订；本文不代表 ACCEPTED ADR。

## 1. 目标与约束

依据根目录 PROJECT.md、DECISIONS.md、TODO.md 和 AGENTS.md。V0.1 分析 Java + Maven + Spring Boot 仓库，生成 Overview、Module Map、Component Map、API Map、Dependency Map、Entry Points 和可解释的 Start Here，在本地界面展示。

核心扫描离线运行，不执行目标项目的构建、插件、注解处理器或应用代码。分析器输出源码事实及其证据，无法确认的部分保留诊断。未来多语言能力通过数据模型和包边界留出空间，不引入插件运行时。

本任务交付技术方案，不创建产品骨架。以下选择均为推荐；库能力依据官方资料，适用性判断属于设计判断。T-0002 新增了隔离 Maven API 实验，结果及其局限见评审记录；尚无性能基准或真实仓库验证。具体依赖补丁版本在工程搭建时核验、固定，不使用浮动版本。

## 2. 核心选型总表

| 决策 | 推荐 | 主要备选与取舍 |
| --- | --- | --- |
| Java Runtime | RepoOnboard 自身最低 Java 21，编译 release=21 | Java 17 可降低安装门槛；21 作为统一开发基线。更高版本暂不设为最低要求 |
| Build Tool | Maven 3.9 系列 + Maven Wrapper，初期单 Java 构建模块 | Gradle 可用，但当前无需另引构建 DSL；Maven 4 的迁移收益与模型 API 兼容性留待评估 |
| CLI | Picocli 4 系列 | 手写参数解析仅适合非常小的入口；这里需要帮助、路径、选项和退出码一致性 |
| Maven Parsing | Maven Model Reader + Model Builder 3.9 系列，限制为本地模型解析 | 纯 XML 无法完整处理继承；调用目标 mvn effective-pom 增加环境依赖及执行风险 |
| Java AST | JavaParser 3 系列 | Spoon 有丰富分析/转换模型；JDT 有 binding API。当前只读提取范围下优先 JavaParser 的 AST 使用方式 |
| Symbol Resolution | 源码声明索引 + 受限项目内解析，按需使用 JavaSymbolSolver | 全 classpath / 近编译器级解析成本高；完全只匹配简单类名会误连 |
| Generic Project Model | Java records 和枚举，引用通过稳定 ID | 暴露 AST 会绑定解析器；通用语言类型系统超出当前需要 |
| Analyzer Boundary | 单进程、单 Java 模块、分包和显式编排 | 多 Maven 模块可强化编译隔离，但现阶段增加配置成本；动态插件不需要 |
| Dependency Graph | 有向边列表 + 按需邻接表 | JGraphT 等库适合复杂算法；V0.1 的筛选、计数与邻域查询用集合足够 |
| Serialization | UTF-8 JSON + Jackson 3 系列，显式 schemaVersion | Gson 可用；Jackson 的对象映射适合模型输出。数据库、二进制格式无即时必要 |
| Local Web Architecture | JDK HttpServer + 打包静态资源 + 只读模型接口 | 纯 file:// 页面数据加载受限；Spring Boot 服务端会增加与本任务无关的容器能力 |
| Frontend | Vue 3 + JavaScript + Vite，单页四视图 | 原生 JS 初期简单但同步筛选状态较分散；React 同样可行，此处选择 Vue 的模板/响应式组织方式 |
| Visualization | Cytoscape.js，先用内置布局和局部子图 | 自绘 SVG 需要维护交互和布局；D3 更底层。复杂布局插件待真实图验证后再决定 |
| Testing | JUnit Jupiter 6 系列；前端 Vitest，关键流程 Playwright | 不依赖 IDE；测试库按相应阶段引入，避免现在搭整套 UI 测试基础设施 |
| Packaging | 可执行 JAR + Windows/POSIX 启动脚本，静态资源随包交付 | Native Image、自带运行时和包管理器分发增加发布矩阵，延后 |

Java 21 只约束工具运行环境，不等同于被分析源码版本。初始验证覆盖 Java 8、11、17、21 常见语法；其他语法按锁定解析器实际能力处理，不承诺全部现代/预览语法。AST 解析不代表能完整解析对应版本的 JDK 类型。

官方资料确认 JavaParser 提供 AST 与独立符号分析能力，Spoon 提供分析与转换模型，JDT 可配置源码路径、classpath 和 binding recovery；选择 JavaParser 是针对本项目范围的判断，不是三者性能排名。[JavaParser](https://github.com/javaparser/javaparser)、[Spoon](https://spoon.gforge.inria.fr/)、[JDT ASTParser](https://help.eclipse.org/latest/topic/org.eclipse.jdt.doc.isv/reference/api/org/eclipse/jdt/core/dom/ASTParser.html)

Picocli 提供命令行与打包相关文档；Wrapper 用于固定项目构建工具。JUnit 当前文档要求运行环境至少 Java 17，与推荐基线兼容。[Picocli](https://picocli.info/)、[Maven Wrapper](https://maven.apache.org/tools/wrapper/)、[JUnit](https://docs.junit.org/6.1.3/overview.html)

## 3. 工程边界和分析流程

建议正式实现阶段使用以下包，均属于同一个 Java 构建模块。此处是设计，不提前创建目录骨架。

| 包 | 职责 | 边界 |
| --- | --- | --- |
| core.model | 通用事实、位置、诊断、分析报告 | 不引用 JavaParser、Maven、Spring 或 Web 类型 |
| analyzer.maven | 模块、构建元数据、源码根、构建依赖 | 不识别 Controller 或 Bean |
| analyzer.java | 解析、声明索引、注解/类型/成员事实 | 不解释 Spring 业务语义 |
| analyzer.spring | 组件、入口、MVC 映射、注入声明 | 消费 Java 事实，框架规则集中在此 |
| analysis | 顺序编排、关系整理、统计、Start Here | 不向 core 泄漏第三方 AST |
| serialization | JSON 输出及格式版本 | 只序列化公开模型 |
| web | 本地只读 HTTP、静态资源、浏览器打开 | 不反向调用目标代码 |
| cli | 参数校验、进度、退出码、生命周期 | 不混入分析规则 |

执行顺序：验证路径 → 发现 Maven 模块 → 解析可用元数据和源码根 → 每文件解析并形成 Java 事实 → 建立模块可见的声明索引 → Spring 语义提取 → 解析依赖和 API → 整理通用模型 → 生成统计与阅读建议 → JSON → 本地 UI。

扫描每个源文件一次，将后续需要的类型、成员、注解表达式、构造参数、位置提取到 Java 专用事实记录；不把 AST 当作最终模型。JavaSymbolSolver 只在后续任务确有收益时接入共享解析结果；若接入导致重复解析，先测量再决定，不能默认全仓库再扫一次。

每个分析阶段返回数据和 Diagnostic，报告状态为 SUCCESS、PARTIAL 或 FAILED。模块损坏、文件语法错误导致 PARTIAL；输入路径无效、根 POM 无法读取且无法确定分析范围等不可继续情况才 FAILED。

## 4. Maven 分析的离线契约

推荐使用官方模型构建能力处理继承、属性插值和 dependencyManagement，而非自行重写完整 Maven 语义。官方 Model Builder 文档列出了这些步骤，也表明模型构建不等同于简单 XML 读取。[Maven Model Builder](https://maven.apache.org/ref/3.9.9/maven-model-builder/)

1. 目标目录以根 pom.xml 为入口；不自动向上寻找另一个项目。模块按声明发现，聚合关系与 parent 继承关系分别记录。
2. 读取 raw model，保留原始坐标、属性表达式、模块路径和来源。XML 禁止 DTD/外部实体；原型必须验证 Reader 的安全配置，必要时在同一读取适配层先拒绝 DOCTYPE。
3. Model Builder 的解析器只允许扫描范围内的本地 parent、模块坐标索引以及本地 Maven 仓库中的精确坐标 POM。尊重 parent.relativePath（含空值禁用默认相对路径）及 GAV 匹配规则。
4. 默认本地仓库为用户 Maven 标准位置，可显式指定其他目录；不读取 settings.xml 中的凭据或远端仓库配置，不安装网络传输组件。缺少 POM/BOM 时返回未解析诊断。
5. 不启动 Maven CLI，不加载项目 .mvn 扩展，不运行 lifecycle 或插件。读取插件配置不代表执行插件。
6. effective model 构建失败时仍保留已读 raw model 和独立可解析子模块。回退仅支持文档化的字面值与本 POM 属性引用展开，检测循环；不把回退结果标为完整 effective model。
7. 字段记录 rawValue、resolvedValue（可空）、resolutionStatus 和 origin；未解析版本显示 unknown，并可查看原始表达式。不用分析器运行 JDK 冒充目标 Java 版本。

T-0002 修订：ModelResolver 只约束外部坐标解析，relativePath 的本地父 POM 读取还会经 ModelSource2。所有文件来源（根、parent、BOM、本地缓存）必须经过统一受限读取层；构造有界 ModelSource2，在关联来源和实际打开时校验真实路径，拒绝逃逸。禁用不受控 FileModelSource 和项目 ModelProcessor 输入，不因缓存命中绕过来源校验。XML 预检与模型读取应使用同一份已限长字节快照，防止检查与实际输入不同；不以简单字符串搜索代替 XML 解析事件检查。

默认分析无 profile 和 activeByDefault 场景；显式 profile 选择可以通过分析选项提供。使用不注册 OS/JDK/属性/文件隐式 activator 的 ProfileSelector，仅保留显式选择和 activeByDefault 规则；原始 activation 声明仍保留供诊断。仅清空 request properties 不足以隔离宿主 OS，这已由 T-0002 实验证实。空白/允许列表属性与受限 selector 同时使用，parent/BOM 也采用相同规则。报告记录所选 profile 和被忽略的激活条件，并将受限结果标为 PARTIAL，不宣称等同于目标 Maven 环境的完整 effective-pom。

Java 版本优先读取有效 compiler release，再看 source/target；java.version 属性只作为有来源的辅助信息。来源冲突保留诊断。Spring Boot 检测可使用 parent、BOM、Boot 依赖和应用注解等多条证据；“发现 Boot 标记”与“版本已解析”分别表示。

源码根支持默认 src/main/java 和已解析 build.sourceDirectory；模块默认限于扫描根真实路径内，外部模块/parent 路径报告未支持。本地仓库 POM 是允许的外部元数据来源。排除 .git、.repoonboard、target 和测试目录，符号链接不允许逃逸扫描范围，记录已访问真实路径以避免循环。插件生成的源码根和动态模块发现延后。

本地仓库内容会影响可解析程度：报告记录选项、所使用 POM 的坐标和内容摘要，重复性要求为相同输入、选项和本地元数据得到相同语义输出，不承诺不同机器天然完全相同。

## 5. Java 与 Spring 解析范围

### 5.1 类型和注解识别

先建立 moduleId + qualifiedName 的声明索引，保留同名冲突。解析显式全限定名、显式 import、同包类型及可以唯一确定的通配符 import；局部/嵌套声明与遮蔽优先按 Java 作用域处理，无法处理就 unresolved。跨模块查找限于可确认的 Maven 编译可见模块关系；不能把整个聚合项目当成一个无差别 classpath。

框架注解使用全限定名白名单，结合 import 与本地同名声明校验；不能见到简单名 Service 就当作 Spring。基础范围支持框架标准注解，不自动递归推断自定义组合注解、AliasFor 或运行时扫描行为。这些情况记录覆盖限制。

默认无需下载第三方 JAR。外部类型可保留明确导入的限定名，但不会凭名称创建仓库内组件。完整依赖 classpath 解析、泛型推导、方法调用图不进入 V0.1 基础范围。

### 5.2 组件、入口和依赖

识别 Controller、RestController、Service、Repository、Component，并单独记录 Configuration 与 SpringBootApplication 入口证据。同一类有多个标记时保存全部角色，统计按唯一组件 ID 去重。UI 必须说明这些是源码声明的组件，尚未验证运行时 Bean 是否启用。

注入候选来自单构造器、明确 @Autowired 构造器和 @Autowired 字段；多构造器的运行时选择规则无法确定时保留候选诊断。单构造器无需注解的规则有 Spring 官方依据。[Spring 注入说明](https://docs.spring.io/spring-framework/reference/core/beans/annotation-config/autowired.html)

关系分为两类：

- DECLARED_TYPE_DEPENDENCY：源码中的依赖类型可以确定，带 CONSTRUCTOR_INJECTION、FIELD_INJECTION 或 TYPE_REFERENCE 证据；只表示静态类型关系。
- UNRESOLVED：目标类型不在模型内或存在歧义，保留注入位置、目标名称和原因，默认不画成确定边。

接口注入不会直接选择某个实现类。即使只找到一个实现，也不足以证实运行时选择；V0.1 可在详情中展示候选名称与推导理由，但不生成假定的注入边。Qualifier、Primary、条件 Bean、XML Bean、工厂方法和 Lombok 生成构造器不纳入初始可靠解析范围。Setter 和 Mapper 依 TODO 对应任务评估，不阻塞核心链路。

对于源码内实际声明的 Repository 接口，可以作为组件图节点；仅因接口名称以 Repository 结尾不能认定组件。Spring Data 自动注册模式若尚不支持，应显示该覆盖限制。

### 5.3 HTTP Endpoint

支持标准 RequestMapping、Get/Post/Put/Delete/PatchMapping 的直接声明，组合类级与方法级路径数组，保存类和方法两处证据。字面量和可确定的本地字符串常量表达式可以展开，其他表达式保持 unresolvedPath；不把占位符原文当成已解析部署 URL。

没有 HTTP method 限制时保存 ANY，而非猜测 GET；类/方法同时限制 method 的组合按 Spring 规则用 fixture 验证后实现，不凭直觉取交集。params、headers、consumes、produces 保留为声明条件，避免同一路径的不同处理器被错误合并。特殊映射、继承或自定义组合注解超出初始支持时给出诊断。[Spring MVC 映射规则](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-controller/ann-requestmapping.html)

路径只处理连接处斜线，保留路径变量、正则和有意义的末尾斜线。输出为应用内声明映射；context-path、代理前缀和运行时配置不推测。隐式 HEAD/OPTIONS 不另计为源码声明 Endpoint。

## 6. 统一模型、ID 与图

| 实体 | 最小字段 |
| --- | --- |
| Project | id、name、modules、languages、frameworks |
| Module | id、relativePath、coordinates、aggregatorId、parentCoordinates、sourceRoots |
| SourceFile | id、moduleId、relativePath、language、parseStatus |
| Component | id、moduleId、sourceFileId、name、qualifiedName、kinds、language、framework、evidence |
| Endpoint | id、componentId、handlerSignature、httpMethods、path、conditions、resolutionStatus、evidence |
| EntryPoint | id、kind、componentId、evidence |
| Dependency | id、sourceId、targetId（可空）、targetName、kind、resolutionStatus、evidence |
| SourceLocation | sourceFileId、startLine、startColumn、endLine、endColumn、symbol |
| Evidence | type、location、relatedLocations、ruleId |
| Diagnostic | code、severity、stage、moduleId/fileId、location、message |

外层 AnalysisReport 包含 schemaVersion、toolVersion、status、options、project、diagnostics、summary、readingGuide 和输入来源摘要。通用核心只承载框架标识和事实，Spring 识别规则属于分析器。

位置行列采用 1-based；未知位置为空，不填 0 或编造行号。POM 字段能取得位置时记录位置，否则至少记录文件和字段路径。路径序列化为扫描根相对路径，统一 `/`；实际读取通过 Path API。默认输出不保存整份源码和绝对用户路径。

ID 以规范化结构键生成（结构化 JSON 元组 + SHA-256，不依赖分隔符拼接）：Module 用相对路径；SourceFile 用相对路径；Component 用模块 ID + 限定名；Endpoint 用组件 ID + 方法签名 + HTTP 方法集合 + 路径 + 条件；Dependency 用起止身份 + kind，证据作为数组聚合。项目身份以扫描内固定根标识表示，V0.1 不解决跨仓库全局唯一身份。

相同代码跨机器移动后 ID 保持稳定；重命名、方法签名或路径改变可能改变 ID，这是预期。重复声明造成键冲突时记录诊断并使用文件身份区分，不静默覆盖。未解析签名使用显式标记的源码表示，不冒充已解析类型。

模型数组按稳定键排序，Map 固定输出顺序；时间和耗时独立于语义快照。Dependency 图不混用 Maven 包依赖和组件关系，分别展示；循环依赖合法存储，不能为布局删边。

JSON 只暴露 DTO，禁用任意多态类型反序列化，UI 校验 schemaVersion，未知主版本给出明确错误。Jackson 为推荐序列化实现，正式依赖坐标与版本在 M1 固定。[Jackson Databind](https://github.com/FasterXML/jackson-databind)

## 7. 本地 UI、交互和数据安全

JDK HttpServer 负责静态资源与只读模型接口；这是对少量本地 HTTP 路由的设计选择，需通过并发与关闭流程测试。[JDK HttpServer](https://docs.oracle.com/en/java/javase/21/docs/api/jdk.httpserver/com/sun/net/httpserver/HttpServer.html)

默认绑定 127.0.0.1，使用操作系统分配端口。路由限于打包资源和当前报告，不提供任意文件读取。使用随机会话路径、Host 校验、同源请求限制、无通配 CORS、no-store 和 CSP；拒绝路径穿越，不将目标源码或元数据作为 HTML 执行。会话随机值不写进可导出的报告。

扫描成功后默认持久化到目标目录 `.repoonboard/` 中的工具专用报告文件，再启动 UI；可通过 --output 指定其他位置。输出文件标识与 schema 必须校验，未知已有文件不覆盖；采用临时文件加原子替换，读写失败保留原文件。目标只读时提示指定可写输出目录，不要求修改源码或 .gitignore。

CLI 建议提供路径参数、--no-open、--output、--port、--help、--version。分析失败时不启动界面；部分结果可以启动并显著提示诊断。退出码建议 0=完整成功、1=不可继续、2=参数错误、3=部分成功；服务存活期间保持前台进程，Ctrl+C 关闭服务。打开浏览器失败只打印可访问地址，不丢弃结果。

四个主视图：Overview 展示统计与覆盖限制；Architecture 先模块后局部组件；API Map 可按路径/方法/模块筛选并查看证据；Start Here 展示有理由的阅读顺序。诊断入口贯穿各视图，不把 partial 报告展示为完整分析。

Vue + Vite 仅用于产品界面开发，不代表增加 JavaScript 仓库分析能力。UI 开发/发布构建需要 Node，最终用户只需 Java；所有 JS/CSS/字体随包交付，不使用运行时 CDN。[Vue 使用方式](https://vuejs.org/guide/extras/ways-of-using-vue.html)、[Vite 生产构建](https://vite.dev/guide/build.html)

## 8. Start Here 的可解释规则

推荐顺序采用明确分组：根 POM → 应用入口 → 直接识别的配置类 → 暴露 API 的 Controller → 与前述组件存在确定静态边的 Service/Repository。按模块分组，先覆盖入口，再补充依赖邻域；每组按可见 Endpoint 数、确定入边数、稳定路径排序，并说明对应计数。

首次默认展示不超过 10 项，可展开其余项目；按文件去重，防止多端点 Controller 占满列表。不生成业务含义猜测：“暴露 POST /login”可来自源码，“负责整个认证业务”不可仅凭类名推出。未知依赖不会参与排序，partial 结果标注推荐依据不完整。

## 9. 测试、验证与发布设计

正式开发时测试随功能进入，不等到 M9 才验证。M9 是汇总和真实仓库验收阶段。JUnit 单元/fixture 测试不运行 fixture 应用，也不依赖远端下载目标依赖。

| 验证层 | 必须覆盖 | 判定标准 |
| --- | --- | --- |
| Maven fixture | 单模块、多模块、parent/聚合不同、空 relativePath、缺失 BOM、属性循环、profile、外部路径、恶意 XML | 无网络和目标执行；字段来源/状态正确；单模块失败可继续 |
| Java fixture | Java 8/11/17/21、损坏文件、同名类/注解、通配 import、嵌套类、跨模块 | 位置准确；未解析状态正确；不产生错误确定边 |
| Spring fixture | 单/多构造器、字段、接口多实现、路径数组、常量、ANY、条件重载、未知组合注解 | 受支持事实与手工期望精确匹配，unsupported 有可见边界 |
| 模型测试 | ID、排序、来源位置、序列化版本、重复声明 | 同输入语义快照稳定；歧义不被覆盖 |
| 集成/CLI | 路径、退出码、输出、只读目录、服务关闭、端口占用、浏览器失败 | 可操作错误、报告可用、资源正常释放 |
| UI | 筛选、证据定位、partial 提示、图阈值、恶意文本、schema 不兼容 | 页面不执行源数据；关键浏览流程通过 |
| 真实仓库 | 小型后中型，再尝试复杂项目 | 固定仓库 commit、人工核对样本、记录覆盖和误报，不只看总数 |

真实仓库验证清单记录 URL、commit、Java/Spring/Maven 特征、环境、扫描参数、耗时、峰值内存、解析失败、Endpoint/组件/边人工期望与差异。候选仓库在对应任务选择并核验适用性；本文未下载或分析第三方源码。

性能建议目标：固定 4 核/8GB 测试环境下，约 1,000 个源码文件的扫描力争 30 秒内、峰值堆 512MB 内。它们是首次测量基准，不是已实现承诺或跨机器保证。存在明显瓶颈时先定位重复解析和全图渲染；不提前引入缓存或并行扫描。

推荐开发命令在 M1 建立后为 Windows `mvnw.cmd test` / POSIX `./mvnw test`；完整验证 `mvnw.cmd verify` / `./mvnw verify`。M7 后发布流程先用锁文件执行前端安装、测试及生产构建，再把资源纳入 JAR 并做打包冒烟验证；Java 单测不应每次重建前端。Wrapper 首次下载及工具自身依赖安装需要网络，发布包的目标仓库分析不需要网络。

V0.1 优先提供 JAR、启动脚本、校验和及必要依赖许可说明；最终许可仍由 T-1006 决定。Windows/macOS/Linux 分别验证路径和浏览器行为。Native Image、自带 JRE、多包管理器发布留在后续决策。

## 10. 主要风险和评审验证门槛

| 风险 | 影响 | 缓解与重新评估条件 |
| --- | --- | --- |
| Model Builder 在不完整仓库上失败 | 版本/继承信息缺失 | raw 回退、字段来源、缺失 POM fixture；本地模式无法隔离网络/宿主输入则重审适配方案 |
| 类型解析误连 | 架构图误导 | 作用域和模块可见性、接口不猜实现；出现错误确定边必须修复规则或降为 unresolved |
| Spring 静态声明与运行时不同 | 条件组件/API 覆盖不足 | 明确“声明视图”、限制诊断；不启动容器补全 |
| AST 不支持目标语法 | 单文件缺失 | 按文件容错并报告；真实目标常见语法失败时评估锁定版本升级或备选解析器 |
| 中型图不可读 | 理解成本上升 | 模块/邻域筛选、节点预算、列表回退；局部布局仍不可读再评估布局插件 |
| 数据模型过早固化或过度抽象 | 返工或实现变慢 | 固定最小实体与证据，序列化版本；AST 不对外暴露 |
| 输出含配置秘密或本地路径 | 数据外泄风险 | 仅输出允许字段、不记录全部属性、环境变量、settings 或源码正文；敏感值 fixture 验证 |
| 前后端打包脱节 | 用户启动后无可用 UI | 发布包离线冒烟测试、资源版本校验、无 CDN |

T-0002 应重点验证最小技术实验的需求：缺父 POM 的离线回退、Reader 的 XXE 防护、profile 隔离、同名类型消歧和接口多实现、局部图布局。可以将需要实验的选择标为待验证/延后，不能把文档调研当作原型通过。确需实验时在评审任务范围内安排隔离验证，避免提前铺开正式产品。
