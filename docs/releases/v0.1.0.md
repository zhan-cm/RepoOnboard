# RepoOnboard V0.1.0

RepoOnboard V0.1.0 is the first public release of the local-first, deterministic
onboarding tool for Java 21, Maven, and Spring Boot repositories.

## Highlights

- Detects Maven modules, Java source structure, Spring components, application
  entry points, HTTP endpoints, and confirmed component dependencies.
- Presents a local read-only Web UI with Overview, Modules, Architecture, API,
  and an explainable Start Here reading path.
- Keeps source locations and Evidence behind important results and reports
  incomplete coverage as `PARTIAL` instead of inventing relationships.
- Runs locally without an LLM, cloud service, database, telemetry, or execution
  of the analyzed application.

## Install

Download `repoonboard-0.1.0.zip` and its SHA-256 file from this release, verify
the checksum, extract it, and run `repoonboard.cmd` on Windows or `repoonboard`
on macOS/Linux. Java 21 or newer is required; Node.js and Maven are not required
for the packaged release.

The archive contains the executable JAR, both launchers, the JAR checksum, and
the project and third-party license notices. See the
[English README](https://github.com/zhan-cm/RepoOnboard/blob/v0.1.0/README.md)
or [简体中文 README](https://github.com/zhan-cm/RepoOnboard/blob/v0.1.0/README.zh-CN.md)
for exact commands.

## Verification

The release gate runs the clean Java/frontend test suite, packaged-JAR offline
fixture analysis, and the native launcher on GitHub-hosted Windows, macOS, and
Linux runners. Real-repository evidence covers fixed revisions of Spring
Petclinic, JHipster Sample Application, and a ThingsBoard boundary trial. The
[public demo](https://github.com/zhan-cm/RepoOnboard/blob/v0.1.0/docs/demo/V0.1-DEMO.md)
uses the fixed JHipster revision and intentionally preserves its `PARTIAL`
status.

## Known limits

V0.1 supports Java + Maven + Spring Boot only. It deliberately uses conservative
static analysis, so Spring Data interfaces without direct annotations and some
wildcard-import cases are missed. Large repositories can consume substantial
memory and produce noisy diagnostics; API rows are not paginated, duplicate
module labels can be ambiguous, and graphs within the rendering budget can
still be dense. See the README for the complete measured limits and evidence.
